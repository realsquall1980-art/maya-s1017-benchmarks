02

测法（可照抄）

  1. DSpark A/B 只改 --dspark off/on 一个变量；其余模型、上下文、conf 0.65、8 CPU threads、端口、GPU 完全相同。同一固定请求：输入 106 tokens、temperature=0 / top_p=1 / max_tokens=512、非流式；每模式先预热 1 次再连测 3 次，6 次正式请求全部 HTTP 200、completion_tokens=512、finish_reason=length。
  2. 双口径分开报，不混加：API 口径 = completion_tokens ÷ 整个非流式请求墙钟；引擎口径 = 引擎日志生成段（每请求记 256+239=495 token）÷ 生成时间。
  3. 长上下文用自造近满窗输入 240,065 tokens，在约 80% 深度埋唯一标记，取回才算 PASS；读入/生成耗时以引擎日志行为准。
  4. GPU 隔离用 进程 PID→GPU UUID + 1 秒 nvidia-smi pmon 采样核对物理卡；测试前后配置文件 SHA-256 一致（2ddce079…a305），确认已恢复 --dspark auto。
  5. 本轮为自定义探针，非 Strata 官方社区 benchmark；Quick tuner 仅单轮记录，不视为基准。

两个模式内部都越跑越快、on 全部排在 off 之后，系统文件缓存可能造成顺序偏差，未做交错 / A-B-A 复验；引擎 auto 与显式 off 的 CPU lane 规划不同（83.9 vs 91.9GB），不能把 off 直接当 auto。结论：维持 auto，不把 +9.5% 当成已证实的长期收益。预热耗时（不计入均值）：off 27.065 s / on 24.740 s。on 的证据边界：进程 argv 确认参数生效且请求通过，该版日志无「DSpark loaded」独立字样，未做内核级 profiling。

05

限制（别直接照搬的地方）

L1 · 口径边界

全部为 solo 单请求（单槽配置），并发未压测；非 Strata 官方社区 benchmark，勿与官方榜单数字直接对齐。

L2 · A/B 强度

每边仅 3 轮、off 全先于 on，存在缓存顺序偏差；结论仅为「有希望的初测」，定案需 off/on/off 交错复验。

L3 · 未覆盖项

未恰好压满 262,144 极限；无 PPL/质量对拍、无视觉与工具调用（/v1/models 只声明 text）、无长时稳定性；思考型模型 max_tokens 给小会空输出（建议 ≥512）。

L4 · 机器特异性

9950X3D 双通道内存（约 96GB/s）是 CPU lane 吞吐的物理上限；别抄我们的 threads/lane 参数——先在自己的机器跑校准，再对比社区 EPYC 多通道机型数字。GPU0 全程存在 Quick tune 瞬态约 1,078MiB 短暂映射（调优后退出），不宣称 GPU0 全程零瞬时活动。
